## **2. Overview**

| Item | Description |
| ----- | ----- |
| Purpose | Provide the SAP 4-sheet report format as a system-managed preset export, replacing the manual extraction process currently handled by Mas Rayyan. Users select "SAP Report" and get a multi-sheet XLSX matching the agreed SAP column structure. |
| Scope | SAP preset definition (fixed column sets per sheet), multi-sheet XLSX generation via **exceljs streaming in analytics-service**, two operational modes (standalone in Phase 2, integrated into PRD-B column picker in Phase 3+), reuse of existing duration (HH:MM:SS) + WIB formatters, sheet selection UI. |
| Key Capabilities | (1) System-managed "SAP Report" preset with fixed sheet definitions. (2) Multi-sheet XLSX output (Report Ticket, Report Conversation, Raw AUX; Report Effective Hour deferred — see B-11). (3) User can optionally deselect sheets. (4) Duration fields formatted as HH:MM:SS via existing formatter. (5) All datetime fields converted to WIB via existing formatter. |
| Outcome | Users generate SAP-formatted reports directly from the system. Manual report extraction process by Mas Rayyan is eliminated for the sheets that ship. |

### **Scope Definition**

| In Scope | Out of Scope |
| ----- | ----- |
| SAP preset definition (fixed column mapping per sheet) | Column registry + configurable column picker UI → PRD-B |
| Multi-sheet XLSX generation (exceljs streaming, analytics-service) | Row-level collections + sync pipeline → PRD-A |
| Standalone mode (Phase 2): SAP preset as a fixed export channel/option | Broadcast export → PRD-C |
| Integrated mode (Phase 3+): SAP preset as saved preset in PRD-B column picker | General configurable column export → PRD-B |
| **Reuse** existing duration (ms → HH:MM:SS) formatter | Scheduled / email delivery of reports |
| **Reuse** existing WIB timezone formatter | Custom SAP template per tenant / per customer |
| Sheet selection UI (user can deselect sheets) | Column reordering or customization of SAP columns (Phase 2) |
| Reuse existing job infra (queue, S3 retention, download link, presigned URL) | **Report Effective Hour sheet (Sheet 3) — DEFERRED** (no attendance data, OQ-D1b) |
| Raw AUX sheet from `agentauxintervals` via new per-interval RPC (OQ-D1a) | Supervisor row-level scoping (no export path scopes below tenant — see B-09) |

## **3. Problem Statement**

| ID | Problem | Impact |
| ----- | ----- | ----- |
| PS-001 | SAP report is generated manually by Mas Rayyan (DB extraction + file assembly). | Slow turnaround (hours/days), human error risk, not scalable, single point of failure. |
| PS-002 | No multi-sheet export capability exists. Current export produces single-sheet XLSX per domain (Ticket OR Conversation OR Broadcast — one file per domain service). | Cannot produce the multi-sheet SAP format in a single job. |
| PS-003 | Raw AUX presence data has no analytics-side export path today. `agentauxintervals` exists in people-service but is only exposed as a per-member/per-reason aggregate (`GetAuxSummary`), not per-interval rows. | Raw AUX sheet needs a new per-interval RPC (OQ-D1a). |

| **Multi-Sheet XLSX Generation** | FR-005 [P0]: System MUST generate a single `.xlsx` file with multiple worksheets, one per selected sheet. FR-006 [P0]: Worksheet tab names MUST be: "Report Ticket", "Report Conversation", "Raw AUX" (and "Report Effective Hour" once shipped) — exactly matching SAP naming. FR-007 [P0]: Each sheet MUST contain its own column headers (row 1) using SAP column names. FR-012 [P0]: "Report Conversation" sheet MUST read from `conversationexportdata` (PRD-A), queried by analytics-service. FR-013 [P0]: "Raw AUX" sheet MUST read `agentauxintervals` (people-service) via a **new per-interval RPC `GetAuxIntervals(memberIds, startDate, endDate)`** returning `{memberId, reasonId, reasonText, startAt, endAt, totalAwayMs}` rows (OQ-D1a — BE-owned). FR-014 [P1, DEFERRED]: "Report Effective Hour" sheet is deferred until an attendance/clock-in data source is decided (OQ-D1b). FR-016 [P0]: Hours MUST NOT be modulo-24 (e.g. `172800000` → "48:00:00") — matches existing formatter. FR-017 [P0]: `null`/`undefined`/negative → "-"; **`0` → "00:00:00"** (matches shipped behavior; do NOT map 0 to "-" — nit 4). FR-019 [P0]: `null` datetime → "-". |

FR-021 [P0]: All shippable sheets MUST be pre-selected by default; the deferred Effective Hour sheet is disabled. FR-022 [P0]: System MUST reject submission if zero sheets selected. FR-023 [P0]: Selected sheets MUST be persisted in `parameters.sheets` for reproducibility, and MUST be part of the duplicate-job key (see §21 / B-12). |

## **7. Error Handling**

| ID | Type | Handling | UI/UX |
| ----- | ----- | ----- | ----- |
| EH-001 | Validation | Zero sheets selected. Reject job creation. | "Pilih minimal 1 sheet". |
| EH-002 | Validation | Date range invalid (start > end, or range > 31 days). Block submission. | Reuse existing message "Date range cannot exceed 31 days". |
| EH-003 | Validation | A selected sheet would exceed the 200,000-row cap for the filters. Reject before generation. | "Data terlalu besar. Perkecil rentang tanggal atau kurangi sheet". |
| EH-004 | Permission | Requester lacks `privacy:view_full_email` and/or `privacy:view_full_phone`. Reject job creation (403). | "Anda tidak memiliki izin untuk mengekspor data PII (SAP Report)". |
| EH-005 | Permission | Requester lacks `statistic:export_sap` or company `features.sapExportEnabled = false`. Reject (403). | "SAP Report tidak tersedia untuk akun Anda". |
| EH-006 | Processing | One sheet's data source unavailable / query error. Mark job FAILED (whole job — no partial multi-sheet output). | "Gagal membuat laporan. Sumber data sheet tidak tersedia". Job is **retryable: true**. |
| EH-007 | Processing | Analytics query times out. **Exactly one** retry allowed (existing retry path refuses `retryCount > 0` — `export-report-job.service.ts:193`), then mark FAILED. | "Gagal membuat laporan. Coba lagi nanti". |
| EH-008 | Validation | Duplicate SAP preset job (same requester + channel `sap` + companyId + startDate + endDate + **sheets**, active). Block creation → 400. | "Permintaan yang sama masih diproses". |
| EH-009 | Rate limit | Requester already has 1 active `sap` job (`MAX_ACTIVE_JOBS_PER_CHANNEL = 1`) or has hit `MAX_JOBS_PER_HOUR = 10`. Reject → 400. | "Terlalu banyak permintaan ekspor aktif. Selesaikan atau tunggu dulu". |
| EH-010 | Data | A selected sheet returns no data for the range. Complete job with headers-only sheet. Job still succeeds. | Informational per sheet: "Sheet {name} selesai tanpa data". |

## **10. Field & Validation**

### **10.1 SAP Preset Job Creation Payload**

Contract = existing `POST /analytics/export-report` (`export-report-job.controller.ts:53`) → gRPC `CreateReportJob { channel, parameters: Struct, userContext }`. **New channel value** `sap` on `ExportReportChannelType`; parameters validated by a new `SapReportParamsDto` with `{ whitelist: true, forbidNonWhitelisted: true }` (matching `export-report-job.dto.ts:40-66`).

| Field | Type | Example | Validation | Required | Default |
| ----- | ----- | ----- | ----- | ----- | ----- |
| `channel` | enum | `"sap"` | `@IsEnum(ExportReportChannelType)` — new value `sap`. | Yes | — |
| `parameters.sheets` | string[] | `["Report Ticket","Report Conversation"]` | Min 1; each must match a defined shippable sheet name. Effective Hour rejected until shipped. | Yes | All shippable sheets |
| `parameters.startDate` | string (ISO) | `"2026-03-01T00:00:00+07:00"` | Valid; before endDate. | Yes | — |
| `parameters.endDate` | string (ISO) | `"2026-03-30T23:59:59+07:00"` | Valid; range ≤ **31** days inclusive. | Yes | — |
| `parameters.statuses` | string[] | `["open","ongoing"]` | Per-channel valid status codes. | No | All |
| `parameters.channels` | string[] | `["whatsapp","instagram"]` | Valid platform values. | No | All |
| `parameters.assignedTo` | string[] | `["<memberId>"]` | — | No | All |

> **Removed in v2.0**: `templateId` (fiction — no template concept in the contract; `SAP_REPORT` inside `parameters` would be rejected by `forbidNonWhitelisted`). B-05.

## **11. Non-Functional Requirements**

| Category | Requirement |
| ----- | ----- |
| **Performance** | NFR-001: Job MUST complete within the existing job timeout for ranges ≤ 31 days. NFR-002: XLSX generation MUST use exceljs streaming — MUST NOT hold all rows in memory. NFR-003: Each sheet's Mongo query MUST use a streamed cursor. NFR-004: Per-sheet row cap = **200,000**; exceeding it rejects the job before generation. This supersedes the 20,000 `*_EXPORT_LIMIT` **for the SAP preset's own code path in analytics-service only**. | **Resource** | NFR-005: analytics-service memory limit MUST be raised from **256Mi → 1Gi** (`devops/k8s/20.analytics-service.yaml`) to host workbook assembly; requests raised proportionally. Named explicitly as a §12 dependency and §18 rollout item. |
| **Reliability** | NFR-006: A SAP job is retried **at most once** (existing retry refuses `retryCount > 0`); failures on invalid request are marked `retryable: false` (nit 15/16). NFR-007: If one sheet fails, the whole job FAILS (no partial output). |

## **15. State Transition Model**

SAP preset jobs reuse the existing offline-report job lifecycle. **The persisted enum is `QUEUED | PROCESSING | COMPLETED | FAILED | EXPIRED`** (`enums/index.ts:1917-1923`); DIPROSES/SELESAI/GAGAL/KEDALUWARSA are Indonesian **display labels**, not states (nit 14). Jobs are created **QUEUED** and flipped to **PROCESSING** by `EXPORT_REPORT_JOB_PROGRESS` (`export-report-job.processor.ts:84-88`).

| Entity | Current State | Action / Trigger | Next State | Allowed Roles | Guard Conditions | Side Effects | Log Field |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| Export Job | — | Requester submits SAP job (channel `sap`) | QUEUED | Roles with `statistic:export_sap` + both privacy perms | Valid ≤31d range, ≥1 sheet, no duplicate, ≤200K/sheet, <1 active `sap` job, <10/hr | Job queued | `sap_preset_job_created` |
| Export Job | QUEUED | Worker picks up job | PROCESSING | System | — | Progress event emitted | `sap_preset_job_processing` |
| Export Job | PROCESSING | All sheets generated + uploaded to S3 (direct multipart) | COMPLETED | System | Generation + upload success | Presigned URL generated, 7-day retention timer starts | `sap_preset_job_completed` |
| Export Job | PROCESSING | Generation fails (query, memory, upload, timeout) | FAILED | System | Failure after ≤1 retry | Error reason stored; `retryable` set | `sap_preset_job_failed` |
| Export Job | COMPLETED | 7-day retention expires | EXPIRED | System | Retention timer expired | S3 file deleted, download disabled | `sap_preset_job_expired` |

## **16. Permission Matrix**

Access to `/analytics/export-report` is **permission-based**, not role-based (`@RequirePermissions([StatisticPermission...])`, `export-report-job.controller.ts:54`). "Agent denied" is expressed by not granting `statistic:export_sap`.

| Download | Job visibility rule (own jobs unless ADMIN/SUPER_ADMIN — `export-report-job.repository.ts:57-74`) |
| View all jobs | ADMIN / SUPER_ADMIN only; SUPERVISOR sees own jobs only (matches shipped behavior) |

#### **Entitlement Gate**

SAP Report is available only when:
1. `company.features.sapExportEnabled = true` — **new** company-level feature sub-document, set manually by ops/CS after the Perjanjian Kerja Sama (PKS) is signed.
2. Requester holds the `statistic:export_sap` permission.

Backend rejects SAP job creation with `FEATURE_NOT_ENABLED` (flag off) or `403` (missing permission). Tab visibility is UX-only — backend is source of truth. (`company.subscriptionTier` from v1.0 does not exist and is removed — B-08.)

## **21. Concurrency, Rate Limit & Idempotency**

Enforced constants (all verified): `MAX_ACTIVE_JOBS_PER_CHANNEL = 1`, `MAX_JOBS_PER_HOUR = 10`, `MAX_DATE_RANGE_DAYS = 31` (`report-job.constant.ts`). Dedup key = `channel + createdBy + companyId + startDate + endDate` (`findActiveDuplicateJob`).

| Scenario | Risk | Required Behavior | Validation |
| ----- | ----- | ----- | ----- |
| Duplicate SAP job (same requester + channel `sap` + companyId + start + end + **sheets**) | Two SAP jobs differing only by sheet selection are indistinguishable to the current dedup key. | **`sheets` MUST be added to the dedup key** (new index field), else the second submission is silently blocked. Duplicate → **400** (not 409); no job id returned by the current path. | QA: submit two SAP jobs differing only by sheet set → both accepted. |

| Integrated mode | Phase 3+: SAP as a saved preset inside PRD-B's column picker. |
