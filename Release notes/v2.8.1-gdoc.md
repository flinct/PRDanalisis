## Highlights

Remaining v2.8.1 work — **Agent Dashboard interactive drill-down**, **SuperAdmin Global Company Access**, **Notification Service expansion**, and **MongoDB read-preference tuning** — is flagged as **backlog carried to the next version**.

## New Features (Shipped)

* **[#3226] Add Response Lead Time (RLT) to Statistic Pre-Aggregation + Frontend** — *Closed (v2.8.0.1)*
RLT (`firstAgentReplyAt − firstAgentAssignmentAt`) was computed and stored per-conversation in `ConversationSLAMetrics` but had zero downstream propagation. This wires RLT through the full pipeline as a 4th responsiveness metric alongside ART/FRT/TTC — synced to people-service, added to analytics-service pre-aggregation, exposed via api-gateway, and shown as a summary card + line chart on the FE Statistic → Responsiveness section with org/team/agent/platform breakdown. Conversation-only (no TICKET_RLT, no RLT SLA breakdown). Backend commit `eb6eeb7e`, frontend commit `3be94d57`.

* **[#2373] Broadcast — Improvement Template (WhatsApp API) with Media** — *Closed (v2.8.1)*
Broadcast templates previously supported only a plain-text header plus a body with variables. This improvement adds media support (image, video, document) in the template header.

* **[#2907] Agent Dashboard — Permission Access to Statistic Page** — *Closed (v2.8.1)*
Gives Agents access to a mini statistic dashboard: guard fix, logic fix, export fix, and backfill.

* **[#3155] Agent Dashboard — Statistic Parameter Improvement** — *Closed (v2.8.1)*
Filter consistency fix plus new metric parameters for the statistic dashboard.

* **[#3248] Add RLT SLA Breakdown (`slaRltSuccess`) — Full Parity with FRT/TTC** — *Closed (v2.8.0.2)*
Gives RLT (Response Lead Time) a configurable SLA threshold, a computed `slaRltSuccess` boolean, and an "In SLA / Over SLA" breakdown card, matching FRT/TTC. New `SLASettingMetricEnum.RESPONSE_LEAD_TIME` configurable via admin Settings → SLA form, system-default threshold 5 minutes. Backend: `SLASettingResolverService` fallback chain extended with `rlt` branch; `ConversationSLAMetrics` schema gains `rltSnapshotConfiguredMs`/`slaRltSuccess`; real-time SLA breakdown pipeline extended with `rltSla`; proto field `ResponsivenessSLABreakdownResponse.rltSla` tag 3. Frontend: 3rd RLT row in Settings SLA form + 3rd RLT card in Statistic SLA Breakdown. Backfill script `tools/scripts/db/backfill-sla-rlt-success.js` (dry-run-first). Surfaced unrelated bug in FRT business-hours pause calculation — flagged for separate investigation.

## Bug Fixes

### Statistic / Responsiveness

* **[#3243] Team Filter on Statistic → Responsiveness Doesn't Search Backend Data** — *Closed (v2.8.0.2)*
The team filter looked like a search box but only filtered the first page of 25 locally-loaded teams — it never hit the backend, so any team beyond the first page was unreachable. Root cause: `useResponsivenessFilterOptions.ts` called `useGetTeamList({ search: '' })` with a hardcoded empty search and left `shouldFilterOption` at its default `true` (cmdk client-side filter). Fix: debounced search state + `limit: 50` + wired `onSearchChange`/`shouldFilterOption: false`, mirroring the existing `useTeamSearch` pattern (single file, +13/-2).

* **[#3250] Responsiveness Team Filter Lets Supervisor Select Any Team** — *Closed (v2.8.0.3)*
The filter ignored per-user scope, letting a Supervisor pick any team instead of only their own. Root cause: `ResponsivenessFilterOptions.tsx` never forwarded `analyticsContext` into the hook, so `isMyOwnTeam` was never sent to the team query. Also gates on `role.code === SUPERVISOR` to match every other team-scoping site in the codebase. Fix: 2 files (+10/-5).
