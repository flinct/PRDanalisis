# Release Notes

**Version:** 2.7.0 (includes v2.7.0.2 & v2.7.0.3)
**Date:** 27-07-2026
**Server Environment:** production
**Release Tag:** prod-2.7.0, prod-2.7.0.2, prod-2.7.0.3

---

## Highlights

This release focuses heavily on **performance optimization and stability**. The headline feature is **Global Search**, enabling cross-domain search across conversations and tickets. WhatsApp integration receives a significant upgrade with **Baileys v7**, new message type support (contact, poll, event), and a restructured sync flow with separated queues. The workspace loads faster with **lazy-loaded accordion panels**, and **SLA calculation moves from cron to event-driven processing**. Connection pooling is tuned per-service to eliminate blank screens under load. Two follow-up hotfixes (v2.7.0.2 and v2.7.0.3) address a **circular reference crash in group messages**, **RabbitMQ consumer ack errors**, and export/data bugs.

## New Features

* **[#2140] Global Search**
Cross-domain search across conversations and tickets from a single search bar. Supports relation labels for linking results across domains.

* **[#1820] Update Baileys Library to v7 rc-10**
Upgraded the WhatsApp Web engine (Baileys) from previous version to v7 release candidate 10, improving connection stability and message handling.

Added support for additional WhatsApp message types: contact cards, polls, and events. Previously only text, media, and location were handled.

Widget live chat now supports copy-paste from system clipboard.

* **[#2393] Create OPEN API Team Inbox**
New public API endpoint for team inbox data, enabling external integrations.

* **[#2209] Improve Ticket Room — Reply from Selected Bubble**
Agents can reply directly from a selected message bubble in the ticket room instead of scrolling to the composer at the bottom.

* **[#2345] Optimize Filter Count and Spam Filter Query**
Optimized database queries for filter counting and spam filtering, reducing query execution time.

* **[#2363] Spintext — Dynamic Configuration**
Spintext configuration is now dynamic via settings UI, eliminating the need for deployment to update spintext rules.

* **[#2434] Add Global Search Config**
Added configuration options for global search behavior in admin settings.

* **[#2112] Conversation — Add Event assignBy Data**
Added `assignBy` field to conversation assignment events, tracking who performed the assignment.

* **[#2277] Auth — Change Validation onboarding**
Modified authentication validation in the onboarding flow (temporary v2.7.0 change).

## New Features (v2.7.0.2 — Performance Hotfix)

* **[#2611] Change Login Flow (Landing Page)**
After login, users now see a loading/progress page before entering the Conversation workspace. This gives the system time to prepare data and run round-robin assignment if configured. Existing sessions skip the loading screen.

* **[#2597] WhatsApp Web — Change Sync Process After Scan**
Separated the WhatsApp history-sync queue from the inbound message queue to prevent sync operations from blocking live message processing. Users can now choose a sync range: 1 week, 2 weeks, or 1 month (default: latest only). Environment variables added: `RABBITMQ_BACKFILL_PREFETCH=3`, `WHATSAPP_HISTORY_SYNC_MAX_AGE_DAYS=30`, `HISTORY_SYNC_BACKFILL_QUEUE_ENABLED=true`.

* **[#2649] FE Minimalis Workspace**
Workspace sidebar now renders collapsed by default. Data for accordion sections (assignment, attributes, client data, related tickets, notes) is fetched only when the section is expanded. Significantly reduces initial page load time.

* **[#2646] SLA Event-Driven Instead of Cron**
SLA calculation moved from periodic cron execution to event-driven processing, reducing database write/read overhead from scheduled bulk queries.

* **[#2647] Improvement Round Robin**
Round-robin assignment now uses batch loop (5 conversations per member per cycle) instead of distributing all at once. Reduced cron frequency.

* **[#2650] Cron Analytics Running Only Once Per Day**
Analytics pre-compute cron reduced to run once daily at 00:00 GMT+7 instead of multiple times per day.

## Bug Fixes

### Conversations

* **[#1132] Reopen Conversation on Disconnected/Deleted Channel**
Fixed a bug that allowed users to reopen a conversation tied to a WhatsApp channel that had already been disconnected and deleted. System now validates channel status before allowing reopens.

* **[#2052] WhatsApp Web — Inconsistency Account Channel Status**
Fixed inconsistent display of WhatsApp Web account channel status across different pages.

* **[#2216] WhatsApp Group Messages Not Displayed + Missing Reply Context**
Fixed a bug where messages from certain participants in WhatsApp groups did not appear in SatuInbox. Reply context was also missing for group messages.

* **[#2227] WhatsApp API — Conversation Created Without Message**
Fixed a bug where a conversation was created from WhatsApp API without any initial message.

* **[#2226] Ticket → Conversation Static Path URL**
Fixed navigation from ticket to conversation generating a static URL path instead of a dynamic route.

* **[#2128] IT Support — Conversation Room Broadcast**
Fixed a bug in the conversation room broadcast feature for IT support.

* **[#2455] Double Message (v2.7.0.2)**
Fixed intermittent issue where messages were sent/displayed twice.

* **[#2531] Maximum Call Stack in Inbound — Circular Reference (v2.7.0.2)**
WhatsApp group messages crashed the conversation service with `RangeError: Maximum call stack size exceeded` when the sender's phone number matched one of the conversation's account channels. Root cause: `handleSenderInfo()` passed a live Mongoose subdocument (with circular internal back-pointers) into `mapMongoToProto()`. Fix: extract only the 4 needed fields instead of recursively mapping the live subdocument, and added `WeakSet` recursion-path tracking to `mapMongoToProto` in libs/common.

* **[#2509] Blank Screen and Loading Issue (v2.7.0.2)**
SatuInbox showed blank screen due to MongoDB connection pool exhaustion. Fix: bumped `MONGODB_CONVERSATION_MAX_POOL_SIZE` to 50 (from default 10) and added new database indexes for frequently queried fields.

* **[#2717] Conversation Room Title (v2.7.0.3)**
Fixed display issue in conversation room title.

### Broadcast

* **[#1207] Broadcast Sent Successfully with Rp 0 Token Balance**
Fixed a bug that allowed broadcasts to be sent even when the client's token balance was Rp 0. Validation now blocks broadcast dispatch when balance is insufficient.

### Tickets

* **[#1810] KPI Card Counter Not Synced During Pagination**
Fixed KPI card counters in the ticket list that did not update when paginating in real-time.

### Leads

* **[#1619] Visit History — Badge Arrangement**

* **[#1625] Visit Detail — Decision Section UI Mismatch**
Fixed Decision section UI in visit detail not matching the design specification.

* **[#1814] Checkbox Overlaps Text in Lead Contact Filter**
Fixed checkbox overlapping text in the lead contact filter selection UI.

* **[#1823] Invalid Validation on Company Phone/Email Fields**
Fixed incorrect validation on company phone number and company email fields in the new contact form.

* **[#1834] Empty State Missing in Add Prospect**
Fixed missing empty state information in the Existing Contact tab on Add Prospect.

### Settings

* **[#1089] Invoice Filters & Export Not Working**
Fixed multiple issues in Settings > Subscription > Payments > Invoice: search input, status dropdown, date filter, and export button were non-functional. Tab state also did not reset after page reload.

* **[#1572] Notification — UTC Time Display**
Fixed notification description showing UTC time instead of the user's local timezone.

### Analytics

* **[#1708] Offline Report Status Not Updating on Pagination**
Fixed offline report status that did not update when paginating or navigating away and back.

### File Support

* **[#1959] File Compatibility — Support HEIC/HEIF**
Added support for HEIC and HEIF image file types, which were previously rejected during upload.

### Shift Management

* **[#1975] Shift Hour Change Not Effecting Members**
Fixed a bug where changing shift hours did not propagate to assigned members.

### Mobile

* **[#2210] Autofill Data on Mobile Sales Form**
Fixed autofill data not working correctly on the mobile sales form.

### RabbitMQ / Export (v2.7.0.3)

* **[#2716] FIX — RMQ Export Job**
RabbitMQ consumer crashed with `precondition_failed: unknown delivery tag` error, causing export jobs to stall. Fix: restarted RabbitMQ container, added auto-heal monitoring script (`mq-autoheal.sh`) with periodic health checks every 5 minutes.

* **[#2718] Export Offline Returns 0 Data (v2.7.0.3)**
Fixed export offline returning empty data in Excel download. Root cause: payload used `userId` instead of `memberId`.

* **[#2719] Conversation Subject Email Too Long (v2.7.0.3)**
Fixed email conversation subjects exceeding 100 characters without truncation. Now truncated with tooltip showing full text.

### Auth (v2.7.0.2)

Modified authentication validation flow at onboarding (temporary for v2.7.0).
