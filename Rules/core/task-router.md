# Task Router

## Purpose
Select the smallest workflow that produces a safe, useful result.

## Precedence
1. Applicable safety, legal, privacy, and platform policies.
2. Explicit user instructions — may change the default working approach.
3. Approved project profile — including its non-bypassable controls (see below).
4. This rules pack.
5. Reasonable assumptions, always labelled as assumptions.

**Non-bypassable controls.** A user instruction that changes the default
approach does NOT authorize bypassing controls the active project profile marks
non-bypassable (e.g. mandatory change-intake brief, approval gates, package
freeze, retention policy, traceability). If a user instruction appears to
conflict with a non-bypassable control, surface the conflict and ask — do not
silently drop the control.

## Classification
Classify work as one or more of: discovery/change request, requirements writing,
requirements review, impact/risk analysis, defect investigation, test design,
test execution/validation, release communication, knowledge maintenance, or
repository maintenance.

Load only the core rule and optional adapters required by that classification.
If the task is ambiguous, state the assumed classification and continue with
the least irreversible action; ask only when a missing decision materially
changes scope, safety, cost, or external impact.
