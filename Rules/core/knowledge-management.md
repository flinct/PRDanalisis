# Knowledge Management

## Tiers
- Canonical knowledge: stable cross-project/system rules with an owner and source.
- Domain knowledge: stable context for a bounded area.
- Reference analysis: reusable reasoning, comparisons, and evidence.
- Working notes: temporary hypotheses and session context.

Store only information that is likely to be reused. Attach source, date, owner
when known, confidence/status, and supersession link where useful. Do not store
secrets, unnecessary personal data, raw long-form documents, or unverified claims.

When knowledge conflicts, preserve both claims and their sources; resolve using
the most authoritative current evidence and the project escalation path. A
project profile MAY make conflict flagging non-bypassable (never auto-overwrite
a conflicting canonical rule; require explicit confirmation). Knowledge is a
navigation aid, not a substitute for source-of-truth verification.
